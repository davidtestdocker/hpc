# Week1 — Linux：程序與資源觀察

本週從終端機裡的 Linux 指令開始，學會看程序、CPU、記憶體和磁碟。只需要理解各課的命令與輸出欄位，不需要先讀專案程式或部署設定。

## 怎麼讀？

按 Day1 到 Day7 閱讀。每課先解釋概念，再說明指令，最後讀「已有結果與解讀」。課文已列出可用的觀察，不需要重新建立環境。

舊紀錄沒有保存的完整輸出會直接說明；為講解而寫的示例也會標示，不會用別週的實驗補成本課結果。

## 每日閱讀順序

| 課程 | 本課要回答的問題 | 指令與材料 |
| --- | --- | --- |
| [Day1：程序與 PID](day1-linux-process.md) | 程序是什麼，誰啟動了它？ | `ps -ef`，PID／PPID 欄位示例；舊 VM 的文字觀察。 |
| [Day2：CPU 排程](day2-cpu-scheduler.md) | 工作如何取得 CPU 時間？ | `nproc`、`yes`、`top`；一個與兩個 yes 的使用率紀錄。 |
| [Day3：上下文切換](day3-context-switch.md) | CPU 如何換一個工作執行？ | 五個 yes 分享四份 CPU 時間的觀察，未保存切換計數。 |
| [Day4：CPU 使用率](day4-cpu-utilization.md) | CPU 時間花在哪裡？ | `top` 的 us／sy／id，加入負載前後的數值摘錄。 |
| [Day5：記憶體](day5-memory.md) | 整機可用量與程序用量怎麼看？ | `free -h`、`ps` 的 RSS 排序與舊觀察。 |
| [Day6：磁碟與 I/O](day6-disk-io.md) | 容量、裝置結構、讀寫統計差在哪裡？ | `df -h`、`lsblk`、`iostat` 的保存摘錄。 |
| [Day7：分析流程](day7-performance-analysis.md) | 如何把觀察變成可檢查的解釋？ | 整理前六天材料，沒有新增實測。 |

## 本週讀完應能做到什麼？

- 從 PID、PPID 看程序與父子關係。
- 區分程序存在、正在使用 CPU、等待其他工作。
- 分清 CPU 使用率、可用記憶體、磁碟容量和 I/O 統計。
- 說明一份輸出顯示了什麼，以及還不足以判斷什麼。
