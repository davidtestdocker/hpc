## 基礎解說

程式是磁碟上的指令；程序是執行中的實例，有 PID、位址空間與資源。執行緒是程序內可被排程的執行單位，多執行緒不等於多台機器。

CPU 排程把可執行的執行緒分配到邏輯 CPU；等待磁碟或網路的工作通常不能靠增加 CPU 解決。CPU 百分比是時間比例，load average 是另一種負載指標，不能直接視為百分比。

記憶體要分程序 RSS、cache 與可用量；磁碟要分容量、吞吐、延遲。定位瓶頸先問「誰在等待什麼」，再挑工具，不是看到單一數字高就下結論。

## 目前環境與實測邊界

### 先認得這幾個詞

| 名詞 | 白話意思 | 本週不要混淆的事 |
|---|---|---|
| Program | 尚未執行的程式檔案 | 檔案存在不表示有程序在跑 |
| Process／PID | 執行中的實例／它的識別號 | 同一程式可有多個 PID |
| Thread | 程序內可被排程的執行單位 | 一個程序可能同時用多個核心 |
| CPU core／logical CPU | 硬體計算資源／系統可排程單位 | 不等於機器數量；SMT 也不代表效能線性加倍 |
| Waiting | 等待 I/O、鎖或其他事件 | 不一定是當機 |
| Context switch | 把 CPU 的執行對象換成另一個 | 切換多不必然代表需要優化 |

例如：API 程序等待 DB 回應時，CPU 可以執行其他可執行的執行緒。若瓶頸是 DB 等待，單純讓 API 取得更多 CPU 不一定改善延遲。這就是先確認等待原因、再調資源的原因。
