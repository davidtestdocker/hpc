# Week1 Day2 — CPU 排程

## 今日目標

理解程序為什麼需要分享 CPU，以及 `nproc` 和 `top` 各自告訴你什麼。

## 排程器在做什麼？

程序中的執行緒需要 CPU 才能執行指令。Linux 排程器（Scheduler）會選擇哪些可執行的執行緒使用邏輯 CPU，並在需要時更換執行對象。

等待鍵盤、磁碟或網路的執行緒，通常不會一直占用 CPU。不能只用「總共有幾個程序」判斷 CPU 是否忙碌。

## 查看可用處理單位：nproc

```bash
nproc
```

當時課文保存的輸出是：

```text
4
```

這表示當時呼叫 `nproc` 的程序有四個可用處理單位。它不能單獨證明機器有四個實體核心；實體核心、邏輯 CPU 和程序可用的 CPU 數量可能不同。

若有四個可用邏輯 CPU，四個持續運算的單執行緒工作就有機會同時執行。這不表示它們永久綁定到特定核心。

## 用 yes 產生持續負載

舊實驗使用：

```bash
yes > /dev/null
```

`yes` 不斷輸出文字，`> /dev/null` 把輸出丟棄，因此終端機不會被文字洗滿。它仍持續工作，可以用來觀察 CPU 使用率。

接著在另一個終端機執行：

```bash
top
```

在程序列表找 `yes`，查看它的 `%CPU`。前景執行的 `yes` 可在原終端機按 `Ctrl+C` 結束；`top` 按 `q` 離開。這裡保留命令來解釋實驗，不需要重新執行才能閱讀結果。

## 已有結果與解讀

舊紀錄保存以下文字觀察，沒有完整 `top` 畫面或原始 log：

| 當時的操作 | 當時的觀察 | 可以怎麼理解 |
| --- | --- | --- |
| 啟動一個 yes | 該程序 CPU 接近 100% | 在當時 top 的顯示方式下，約使用一個邏輯 CPU 的時間。 |
| 同時啟動兩個 yes | 兩個程序都接近 100% | 兩個單執行緒工作都取得接近一份 CPU 時間。 |

單一程序的 100% 與整台機器的 100% 不一定使用相同分母。上述數值也不能證明兩個程序永久固定在不同核心。

## 今日重點

`nproc` 看可用處理單位，`top` 看採樣期間的 CPU 使用率。排程的對象是執行緒；多執行緒程序可以使用超過一個邏輯 CPU 的時間。
